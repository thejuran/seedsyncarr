<objective>
Close the D-03 audit's one drift risk in the Python app: `Context.print_to_log` (run on every `Seedsyncarr()` construction, i.e. at startup and again on the settings-reload/`ServiceRestart` path) redacts from a hand-kept set. Make it redact by `Config.secret_fields()` and add two sentinel tests — a `print_to_log` unit test and an end-to-end startup/reload test — so SEC-01's "at startup or on settings reload" clause has a regression guard on the Python side too.

Purpose: SEC-01 covers startup AND settings reload. The shell fix (Plan 119.1-01) covers the entrypoint; this plan covers the app's own startup logging so a new `secret=True` field cannot leak in debug mode. Honest note (RESEARCH Pattern 3): today's hand list already covers all five fields, so these tests pass before the change — they are drift guards, not the RED demonstration. The RED is Plan 119.1-01.
Output: redaction change, config-parse hardening (RED-first), and three test additions, committed; quick-run tails for the SUMMARY.

Codex adversarial finding (pass 1) folded in: `Config.from_str` reads options with a default `configparser.ConfigParser()` (BasicInterpolation) OUTSIDE its `try` block; a secret such as `remote_password = SENTINEL%(missing)s` raises `InterpolationMissingOptionError` whose message contains the whole value, and `Seedsyncarr.__init__` catches only `ConfigError`/`PersistError`, so today the value reaches the startup traceback on stderr (or `logger.exception` on reload). Task 3 closes this path. Codex pass 2 refinement: the sanitized error must NOT be a `ConfigError`, because `Seedsyncarr.__init__` catches `ConfigError`/`PersistError`, copies the file to `.bak` and writes DEFAULTS — the default `api_token` is empty and `web_app.py` allows unauthenticated requests when it is empty, so a hand-edited password with an unescaped `%` would silently strip authentication and start an open web server. Interpolation failures are therefore fatal: no reset, no web server, non-zero exit (container restart loop under production's `unless-stopped` policy — acceptable; an unauthenticated server is not).
</objective>
