### `src/docker/build/docker-image/setup_default_config.sh` (startup script)

**Analog:** the file itself. Current full contents (36 lines):

```bash
 1  #!/bin/bash
 3  # exit on first error
 4  set -e
 6  CONFIG_DIR="/config"
 7  SETTINGS_FILE="${CONFIG_DIR}/settings.cfg"
 8  SCRIPT_PATH="/app/python/seedsyncarr.py"
10  replace_setting() {
11      NAME=$1
12      OLD_VALUE=$2
13      NEW_VALUE=$3
15      echo "Replacing ${NAME} from ${OLD_VALUE} to ${NEW_VALUE}"
16      sed -i "s/${NAME} = ${OLD_VALUE}/${NAME} = ${NEW_VALUE}/" ${SETTINGS_FILE} && \
17          grep -q "${NAME} = ${NEW_VALUE}" ${SETTINGS_FILE}
18  }
20  # Generate default config
21  python ${SCRIPT_PATH} \
22      -c ${CONFIG_DIR} \
23      --html / \
24      --scanfs / \
25      --exit > /dev/null 2>&1 > /dev/null || true
27  cat ${SETTINGS_FILE}                      # LEAK - remove
30  # Replace default values
31  replace_setting 'local_path' '<replace me>' '\/downloads\/'
33  echo
34  echo
35  echo "Done configuring seedsyncarr"
36  cat ${SETTINGS_FILE}                      # LEAK - remove
```

**Must keep exactly once (the D-04 test rewrites these strings in a temp copy and asserts `count == 1`):**
- `CONFIG_DIR="/config"` (line 6)
- `SCRIPT_PATH="/app/python/seedsyncarr.py"` (line 8)

**Must keep:** `#!/bin/bash`, `set -e`, the `> /dev/null 2>&1` on the generation step (RESEARCH Pitfall 3), git mode `100755` (verified today: `git ls-files -s` shows `100755 4334ef8b…`). Edit in place; do not recreate the file with Write (Pitfall 4). Never add `set -x`.

**Caller contract** (`src/docker/build/docker-image/entrypoint.sh`, lines 91-100 of the file):
```bash
# setup_default_config.sh is idempotent for an existing settings.cfg: the
# default-generation step is guarded with `|| true` and the replace step is a
# no-op once the placeholder is gone. ...
if [ -x /scripts/setup_default_config.sh ]; then
    log "Running config setup as uid ${PUID}"
    gosu "${PUID}:${PGID}" /scripts/setup_default_config.sh || \
        log "config setup returned non-zero (existing config — continuing)"
fi
```
`[ -x … ]` is why the exec bit matters. Today `replace_setting` returns non-zero on existing configs, so `set -e` exits before line 33. That is why a status line placed at the end would never print (Pitfall 1). Guard the replace step with `grep -qF "local_path = <replace me>"` (RESEARCH Pattern 1). The entrypoint comment ("the replace step is a no-op") becomes accurate. Updating it is optional and stays inside D-01/D-02.
