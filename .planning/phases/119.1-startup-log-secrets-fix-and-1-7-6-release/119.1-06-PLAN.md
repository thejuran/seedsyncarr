<objective>
Close the write side of D-03 (codex pass 3): `Config.to_str` feeds each value to `configparser.ConfigParser.set`, which under BasicInterpolation raises `ValueError` containing the whole value for a bare `%`; `from_str` reads `a%%b` as `a%b`, so an escaped-percent secret on disk crashes at the next `persist()` with the password in `main()`'s `logger.exception` traceback, aborting the reload. The config-set API stores raw values with no `%` check, so a UI-entered password with `%` hits the same path. Fix by escaping `%` -> `%%` on write (read semantics unchanged, byte-compatible for every value without `%`), sanitizing any remaining serialization failure value-free, and proving it RED-first on the real reload-persist path.

Purpose: SEC-01's "at startup or on settings reload" clause must hold on the reload's persist step, not only on construction. Plan 119.1-02 covers construction (read); this plan covers write-back.
Output: `to_str` escape + `ConfigSerializationError`, RED-first tests (round-trip, sanitized failure, reload-persist), SUMMARY sweep table with file:line verdicts.
</objective>
