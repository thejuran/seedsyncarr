# Phase 119.1 Plan 06: Percent-safe config write and value-free serialization failures Summary

`Config.to_str` now writes every `%` as `%%`. The unchanged `from_str` reads that back as a single `%`, so any value, including a password with `%` typed in the UI, survives save -> restart -> reload unchanged. Before this fix, `ConfigParser.set` raised `ValueError` with the whole password in its message. That happened on the periodic persist, on the "Last persist" before a UI restart, and on shutdown, and `main()`'s `logger.exception` then printed the password to stdout and the app log and stopped the reload. Any serialization error that could still occur is now a value-free `ConfigSerializationError`. It is raised before `Persist.to_file` creates its temp file, so settings.cfg is never partly written.
