# Phase 119.1 Plan 01: Startup script stops dumping settings.cfg Summary

The container startup script used to `cat` the whole settings.cfg into the container log twice (passwords, API keys, tokens). It now prints only one status line, `Config ready at /config/settings.cfg (existing config kept|default config generated)`. A sentinel test locks this in: it reads every secret field from `Config.secret_fields()`, was confirmed failing before the fix and passing after, and runs in CI.
