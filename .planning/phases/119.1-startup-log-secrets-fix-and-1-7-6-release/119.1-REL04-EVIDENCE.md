Hygiene: only test names, exception class names and counts are recorded. No secret value, no test

the leak, so their raw pytest output did contain the random test sentinels (the count is noted);

Method: every RED run was made in a throwaway detached `git worktree` under the session scratchpad
at the plan's RED `test(...)` commit, with the project venv interpreter
(`seedsyncarr-5QbP0KwB-py3.12`), then the worktree was removed with `git worktree remove --force`
(each run printed `worktree removed`).

```
PY="$(cd src/python && poetry env info -p)/bin/python"
git worktree add --detach <scratch>/wt-<label> <sha>
cd <scratch>/wt-<label>/src/python && "$PY" -m pytest <files> -q -p no:cacheprovider -o addopts="" -rfE
git worktree remove --force <scratch>/wt-<label>
```

Failure reasons were taken from the `E   AssertionError ...` lines (all field-name-only or
class-name-only messages); exception classes were counted with `grep -o` on the class names.
