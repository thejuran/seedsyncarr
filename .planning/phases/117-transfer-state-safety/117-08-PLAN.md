<objective>
Close the gap codex found in B2: a transfer that was submitted to lftp but never observed in a successful status (parse failure immediately after the QUEUE) is DEFAULT in the model, so with status unavailable AutoQueue can re-submit it after the cooldown and a successful local scan showing a preallocated size can mark it DOWNLOADED (committing it, firing auto-extract, exposing it to delete). Protect such transfers until the first successful status reconciliation (XFER-02, D-01).

Purpose: the phase goal is "never make a re-queue, auto-queue, or delete decision from a transfer state it did not actually observe". Returning None (Plan 05) protects transfers that were observed at least once; this plan protects the ones that were never observed. Placement is Claude's discretion: the set lives in LftpManager (the one object that knows a queue command was actually sent and whether the next status was available), is surfaced to the model as the existing QUEUED state, and is purely in-process (persistence is out of scope per spec).

Output: three edited production files, two extended unit test files; commit `fix(117-08): protect submitted-but-unobserved transfers until first successful status (B2)`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| QUEUE command -> lftp -> next status poll | Between lftp accepting a job and the first successful `jobs -v` parse, the only evidence of the transfer is in-process; a parse failure in that gap (possibly induced by a remote filename) must not turn an unobserved transfer into a decision |
| local scan -> ModelBuilder DOWNLOADED derivation | A preallocated/sparse local file reads as complete while the transfer has not been observed |
