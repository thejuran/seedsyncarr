<objective>
Fix B3: measure remote and local size-stability only on the clock of successful scans by adding two non-serialized successful-scan properties to `ControllerStatus`, writing them from `Controller._update_controller_status` only when a scan did not fail, and pointing `AutoQueue`'s stability histories and `sweep_accept` at them (XFER-04, XFER-05). The UI clocks and the re-queue cooldown are untouched.

Purpose: failed scans leave the model's sizes stale (ModelPipeline does not apply them) while today's clock keeps advancing, so a scanner outage spanning the window makes a file look stable with no fresh evidence. Tying the clock to the same events that update the sizes satisfies D-03 and D-04 directly.

Output: three edited source files, three extended test files; commit `fix(117-06): measure auto-queue stability on the successful-scan clock only (B3)`.
</objective>
