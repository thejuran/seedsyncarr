<verified_facts>
Read from source during research; recheck at implementation time per D-07.

Defaults (src/python/seedsyncarr.py `_create_default_config`, lines 387-435; upgrade backfills in src/python/common/config.py 575-647):
- `[General] api_token` = empty: API authentication off
- `[General] webhook_secret` = empty: webhook verification skipped
- `[General] webhook_require_secret` = `False`
- `[Encryption] enabled` = `False`: stored secrets plaintext
- `[AutoDelete] enabled` = `False` (UI name: Post-Import Pruning), `dry_run` = `False`, `delay_seconds` = `60`
- None of `webhook_secret`, `webhook_require_secret`, `[Encryption] enabled` has a Settings UI control; they are set in `settings.cfg` (Docker: `/config/settings.cfg`)

Always-on controls and their exact scope (no config switch):
- CSP header on every response
- Rate limiting only on: Sonarr/Radarr webhook endpoints, the POST config-set endpoint (`/server/config/set`, registered with add_post_handler in src/python/web/handler/config.py; config-get is not rate-limited), Sonarr/Radarr test-connection, bulk-command, status. Other endpoints are not rate-limited.
- File names sanitized for CR/LF and control characters before reaching log lines (per call site, not a global filter)
- IP-resolution guard on the Sonarr/Radarr URL only when testing a connection, not on live queue requests

Webhook verification:
- SeedSyncarr checks an HMAC-SHA256 of the request body in the `X-Webhook-Signature` header when `webhook_secret` is set; missing or wrong signature returns 401. `webhook_require_secret = true` with no secret returns 503 for every call. `webhook_require_secret = False` (the default) rejects nothing by itself.
- Sonarr and Radarr send only fixed custom headers or basic auth; they do not sign the body (Sonarr and Radarr `WebhookProxy.cs` both read; research assumption A1 is confirmed). The incompatibility applies to direct, unsigned Sonarr/Radarr webhooks: a configured secret rejects each call with 401, and `webhook_require_secret = true` with no secret rejects each call with 503. Either way imports are never confirmed and pruning stops (nothing is deleted).
- The webhook paths are exempt from the Bearer check, so `api_token` does not protect them.

Exposure:
- The app binds 0.0.0.0; both Docker examples publish 8800 with no host IP, so Docker publishes on all host interfaces.
- The server injects `api_token` into the served UI page, so anyone who can load the UI has the token.

Cleanup flow:
- Pruning is scheduled only when pruning is enabled and a webhook confirmed the import. When the delay timer (`delay_seconds`) fires, the controller (src/python/controller/controller.py `__execute_auto_delete`, src/python/controller/auto_delete_manager.py) rechecks that pruning is still enabled, logs instead of deleting in dry-run mode, refuses anything SeedSyncarr did not download, and defers when another operation holds the release, when the release or a child is still mid-lifecycle (extracting, a pack sibling still downloading), or when not every video in a pack has been imported. A deferred delete is retried every `delay_seconds` up to 24 times and then given up with a warning until the next import webhook (docs/CONFIGURATION.md AutoDelete table). So deletion is attempted after the delay, subject to safeguards; it is not automatic on timer expiry.
- Pruning deletes the local copy only (delete_local); the remote copy is not touched.
