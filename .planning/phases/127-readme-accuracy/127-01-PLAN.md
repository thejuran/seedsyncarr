<verified_facts>
Read from source during research; recheck at implementation time per D-07.

Defaults (src/python/seedsyncarr.py `_create_default_config`, lines 387-435; upgrade backfills in src/python/common/config.py 575-647):
- `[General] api_token` = empty: API authentication off
- `[General] webhook_secret` = empty: webhook verification skipped
- `[General] webhook_require_secret` = `False`
- `[Encryption] enabled` = `False`: stored secrets plaintext
- `[AutoDelete] enabled` = `False` (UI name: Post-Import Pruning), `dry_run` = `False`, `delay_seconds` = `60`
- None of `webhook_secret`, `webhook_require_secret`, `[Encryption] enabled` has a Settings UI control; they are set in `settings.cfg` (Docker: `/config/settings.cfg`)

Always-on controls and their exact scope (no config switch):
- CSP header on every response
- Rate limiting only on: Sonarr/Radarr webhook endpoints, POST config-set, Sonarr/Radarr test-connection, bulk-command, status. Other endpoints are not rate-limited.
- File names sanitized for CR/LF and control characters before reaching log lines (per call site, not a global filter)
- IP-resolution guard on the Sonarr/Radarr URL only when testing a connection, not on live queue requests

Webhook verification:
- SeedSyncarr checks an HMAC-SHA256 of the request body in the `X-Webhook-Signature` header when `webhook_secret` is set; missing or wrong signature returns 401. `webhook_require_secret = true` with no secret returns 503 for every call.
- Sonarr and Radarr send only fixed custom headers or basic auth; they do not sign the body. With a direct Sonarr/Radarr webhook, either setting rejects every import webhook, so imports are never confirmed and pruning stops (nothing is deleted).
- The webhook paths are exempt from the Bearer check, so `api_token` does not protect them.

Exposure:
- The app binds 0.0.0.0; both Docker examples publish 8800 with no host IP, so Docker publishes on all host interfaces.
- The server injects `api_token` into the served UI page, so anyone who can load the UI has the token.

Cleanup flow:
- Pruning is scheduled only for releases SeedSyncarr itself downloaded whose import was confirmed by webhook, only if pruning is enabled; it waits `delay_seconds`, and in dry-run mode logs what it would delete instead of deleting. Pruning deletes the local copy only; the remote copy is not touched.
