<design_choices>
Key validation (CR-01). After the existing empty/whitespace-only check, strip the key. Then accept it only if every character is printable ASCII with no space, i.e. it fully matches the character class 0x21-0x7E. That is exactly the set `requests`/`http.client` accept in a header value without raising InvalidHeader or a latin-1 encode error. It is deliberately looser than "alphanumeric only": real Sonarr/Radarr keys are 32 hex characters, but rejecting hyphens or underscores could break an install behind a proxy that uses its own key format. The user-facing error never repeats the key.

Logging (CR-01). Replace `self.logger.exception(...)` with an ERROR that carries only `service_name` and `type(e).__name__`, with no exc_info. Validation stops InvalidHeader for stored keys, but other exception types raised inside requests/urllib3 can also embed header or URL values in their message, so this boundary never logs the message or the traceback. The user gets the generic "An unexpected error occurred" as before.

No new redaction pattern is added to `SerializeLogRecord._redact_sensitive`. A bare key has no recognisable shape, so the reliable fix is never to log exception text at this boundary. The SSE serializer is still exercised in the regression test as the second output path.

rate_limit (WR-01). The signature becomes `rate_limit(max_requests: int, window_seconds: float, *, logger: logging.Logger)`, with no default. An explicit `logger=None` raises `TypeError("rate_limit requires a logger")`. The module-level `logger = logging.getLogger(__name__)` and the `globals()["logger"]` lookup are removed (this also resolves the shadowing noted in IN-02 as a side effect; IN-02 itself stays out of scope). StatusHandler takes `(status, context)`, the same `(dependency, context)` order ConfigHandler uses. IN-03 (redundant constructor args) is out of scope, so no constructor refactor beyond this.

No live CR-01 check on the NAS. A live check would mean writing an invalid key into the sandbox config and then restoring the real key, which requires reading the real key. That conflicts with "never print API keys" and with the owner's standing decision not to touch the sandbox Sonarr key. The unit regression uses a real InvalidHeader through the real ConfigHandler and both real output formatters, which is the same path the verifier reproduced.
</design_choices>
