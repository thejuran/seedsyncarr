Why the webhook for this scenario is root-level (sourcePath `/data/torrents/SSA122.Rar.Pack`): during EXTRACTING the extracted .mkv is inside the excluded staging dir, so by design (the Bug 1 fix) no extracted child is in the model to match. A root-level notice for a root already committed as downloaded is accepted with no child credit, so coverage treats the root as fully imported; this is the only accepted shape mid-extraction and exercises the same EXTRACTING state guard and re-arm path the record describes. A RAR-volume basename must NOT be used: it would add a non-video child credit and leave the .mkv uncovered, so the delete would be given up after 24 deferrals.
Why autodelete.delay_seconds is lowered temporarily (Claude's discretion, D-08 restores it): the timer reads delay_seconds at arm time (controller.py ~1091; validator int_positive, so 1+ is allowed). A ~1 GB extraction takes seconds, far less than 300 s, so with 300 s the timer would never fire during EXTRACTING. 2 s is used; evidence states the delay value. lftp.rate_limit is NOT changed in this plan.
