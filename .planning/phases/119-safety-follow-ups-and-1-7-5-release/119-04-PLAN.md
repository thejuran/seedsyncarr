<objective>
Build the completion-evidence foundation for IMP-02 as two new, independently testable modules: `ArrQueueClient` (HTTP to Sonarr/Radarr `/api/v3/queue/details`) and `CompletionGate` (snapshot cache, capped backoff, strong-identity match, verdict, lifecycle-scoped proof cache, hold registry with transition-only logging). No controller wiring in this plan — 119-06 wires it (and consumes a proof on transfer submission); 119-07 feeds `holds` into the model and invalidates proofs on lifecycle reset / root removal.

Two codex adversarial findings shape the design: (1) a proof cached by name + remote size would stay PROVEN across a same-name re-grab whose client preallocated the original size, bypassing both submission checks — so proofs carry a download identity, live evidence is evaluated first and overrides the cache, and an explicit `invalidate` hook exists; (3) dropping malformed queue records before deciding completion converts uncertainty into PROVEN — so malformed records are preserved as `valid=False` and hold the root they match. Codex pass 2 added two more: (1b) `invalidate` that only drops `_proofs` leaves the completed record in `_snapshots` until the refresh deadline, so a verdict taken in that window recreates PROVEN from stale evidence, and a configuration key of service codes only lets an arr URL switch reuse the old server's snapshots — so invalidation fences the name on per-target snapshot generations until fresh evidence arrives, and the cache is keyed by full integration identity; (3b) a buffered `requests.get` enforces the size cap only after downloading everything and the read timeout is not a total deadline — so the response is streamed with bounded accumulation and an overall wall-clock budget.

Purpose: implement the exact queue predicate verified in RESEARCH (D-05) amended by D-16/D-17, so a sparse-file size plateau can never start a transfer and an unavailable/ambiguous/missing/unverifiable arr entry always holds.
Output: `src/python/controller/arr_queue.py`, `src/python/controller/completion_gate.py`, and their unit test files (Wave 0 gaps from VALIDATION.md).
