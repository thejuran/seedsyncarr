<objective>
Add the explicit submitted-but-unobserved guard to the auto-delete Timer (DEL-01, backlog 999.3), mirroring `CommandProcessor._is_submitted_unobserved` (409 for manual Delete/Extract). Today protection is indirect (evidence gate + stale-retained model state); the Timer × unavailable-status × submitted-root combination is untested, and the set is read cross-thread without a lock.

The set guard alone is not sufficient (codex adversarial finding 2, verified against HEAD): `Controller.__process_commands` releases `__model_lock` before `CommandProcessor.handle` submits, and `__execute_auto_delete` releases `__model_lock` before `delete_local`. A Timer can pass every guard on an empty submitted set, a concurrent QUEUE can then submit the root, and the Timer can delete the copy lftp is writing. Closing this requires serializing the *decision-to-destructive-operation* window with the *submission* window: a per-root operation reservation (`RootReservations`) shared by queue submission and both deletion paths, held through the destructive call.

Purpose: a pending auto-delete can never delete a transfer that was just submitted and not yet observed, and can never overlap a submission in flight; it defers and retries safely through the existing bounded re-arm machinery (ROADMAP success criterion 2).
Output: lock-protected submitted set with add-before-queue ordering, the Timer guard, the per-root reservation wired into Controller and CommandProcessor, and RED-first regressions including barrier-controlled concurrency tests.
</objective>
