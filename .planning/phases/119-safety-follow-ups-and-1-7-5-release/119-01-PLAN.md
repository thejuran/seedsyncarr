<objective>
Re-establish a trustworthy LFTP command boundary after a pexpect timeout (XFER-06, backlog 999.2). Today `Lftp.__run_command` leaves the pty stream desynchronized after a TIMEOUT: the late prompt of the timed-out command satisfies the NEXT command's `expect`, so the next `jobs -v` returns stale/empty output that parses as `[]` and can clear observed and submitted-transfer protection.

Purpose: a delayed prompt or stale output can never become a trusted empty job list (ROADMAP success criterion 1).
Output: `Lftp.__synced` state, a nonce sentinel resync (`echo SEEDSYNCARR-SYNC-"<nonce>"-END`), status unavailable (`None`) until resynchronized, and a RED-first regression test file.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-119-01 | Tampering | `Lftp.__resync` sentinel command | mitigate | Sentinel body is a `secrets.token_hex(8)` nonce only — no user- or remote-controlled text ever enters the echo line |
| T-119-02 | Spoofing | Stale pty output matched as a fresh command boundary | mitigate | Marker uses quote-split echo so the tty echo of the command cannot match; a new nonce per attempt so an old marker never satisfies a later resync |
| T-119-03 | Denial of service | Wedged lftp blocks the controller during resync | mitigate | `RESYNC_TIMEOUT_SECS = 15` (not 180 s); LftpManager stall breaker unchanged |
| T-119-04 | Information disclosure | Command output logging | accept | Existing `sanitize_log_value` on debug output; no credentials in sentinel |
