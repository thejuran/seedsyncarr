<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (Angular HttpClient) -> api.github.com | Third-party origin; must never receive the app token |
| Browser -> SeedSyncarr origin /server/* | Own API; Bearer token required when configured |
| Request URL string -> interceptor | URL is code-constructed today, but any future caller could pass an absolute or odd URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-121-01 | Information disclosure | authInterceptor attaching Bearer to the GitHub update check (CWE-201/522) | mitigate | isOwnApiRequest gate: exact `parsed.origin === window.location.origin` AND pathname under "/server/"; D-11 regression test on the literal GitHub URL plus VersionCheckService integration pin |
| T-121-02 | Spoofing | Origin confusion via //host, /\host, userinfo, look-alike host, port or scheme change | mitigate | WHATWG `new URL(url, ownOrigin)` (same parser the browser uses) + exact origin equality; one Karma test per trick |
| T-121-03 | Information disclosure | Unparseable / unexpected URL bypassing the check | mitigate | try/catch around URL parse returns false (fail closed, D-03); "http://[" test |
| T-121-04 | Information disclosure | Token or URL written to the browser console | mitigate | console.warn uses a fixed message with no arguments; test asserts warn args contain neither the token nor the URL |
| T-121-05 | Denial of service (self) | Own /server/ calls lose the token (false negative) causing 401s | mitigate | Positive tests for relative and absolute same-origin /server/ URLs; full Angular suite; E2E token run in plan 02 |
| T-121-06 | Elevation of privilege | Server-side Bearer check weakened | accept | Out of scope and unchanged (SC4); diff check against c3d2788 proves src/python untouched |
</threat_model>
