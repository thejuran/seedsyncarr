<objective>
Make Save apply the shared key rule to Sonarr/Radarr API keys (trim, or refuse), move Test Connection onto the same shared rule, and stop the save response echoing secret values (D-07).

Purpose: a key pasted with a stray space or line break is the false all-clear this phase removes. Saving it trimmed (or refusing it with the wording Test Connection already uses) means what is stored is always what Test Connection approved. Separately, the save confirmation currently repeats every secret back in the response body, which the browser then writes to its console.

Output: changes to `web/handler/config.py` and its unit and integration tests. No UI change, no config PROP change.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser / API client -> POST /server/config/set | Untrusted section, key and value cross here; value may be a secret |
| server -> HTTP response body -> browser console | The settings page logs the save response text, so anything echoed leaves the server and lands in the console |
| server -> application log | New warning line on refused secret saves |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-128-04 | Information disclosure | __handle_set_config success body | mitigate | "<section>.<key> updated" for every (attr, field) in Config.secret_fields(); integration sweep test_set_secret_fields_never_echo_value fails if any current or future secret echoes |
| T-128-05 | Information disclosure | __handle_set_config refusal body | mitigate | Fixed strings only: "Invalid request body", "<Svc> API key contains invalid characters", "Invalid value for <section>.<key>"; never str(e) or value_str for a secret; pinned by test_set_secret_config_error_does_not_echo_value |
| T-128-06 | Information disclosure | new warning log line | mitigate | Logs section, key (both already validated to exist in the config) and type(e).__name__ only; value and exception message never passed to the logger (122 D-14 convention) |
| T-128-07 | Tampering | stored Arr key later used as X-Api-Key header | mitigate | Save refuses any key failing is_valid_arr_api_key, so CR/LF or control characters cannot be stored through the API |
