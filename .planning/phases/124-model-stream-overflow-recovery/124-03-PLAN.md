## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser tab -> /server/stream | Untrusted, unauthenticated-by-design EventSource client; may stall deliberately |
| web thread -> Controller __model_lock | Resync briefly takes the model lock from a per-connection thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-06 | Denial of Service | ModelStreamHandler resync state (CWE-400) | mitigate | Pending state is one bool (D-04); queue stays capped at maxsize; snapshot is built only when about to be yielded, never queued; tests assert queue <= maxsize and a single resync call for many drops |
| T-124-07 | Denial of Service | Repeated resyncs from a client that stalls forever | mitigate | A blocked socket write blocks get_value(), so no resync is computed while stalled; each resync costs one model snapshot under the lock (same cost as an existing page load); no time-based retry loop |
| T-124-08 | Tampering | Log injection via the resync warning (CWE-117) | mitigate | Warning contains only integer counts; test asserts no file names appear; any future name must go through sanitize_log_value |
| T-124-09 | Information Disclosure | model-init contents | accept | Same data the tab already receives on connect; no new fields or endpoints |
| T-124-10 | Tampering (race) | miss/duplicate between discard and snapshot | mitigate | _discard_backlog runs inside resync_model_files' __model_lock block and rebaselines the dropped count there; tests prove post-resync events delivered exactly once |
</threat_model>
