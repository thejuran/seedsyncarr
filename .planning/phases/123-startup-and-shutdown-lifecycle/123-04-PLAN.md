<objective>
Fix the false-alarm scanner error that every normal `docker restart` logged in Phase 122 (D-01). Cause, per RESEARCH: `tini -g` sends SIGTERM to the whole process group. The forked scanner children run SIGTERM as SIG_DFL, so they die at once. On its next cycle the ControllerJob health check sees them dead and logs ERROR `Scanner process(es) died unexpectedly` plus `ScannerProcessDiedError`, racing the main thread's orderly shutdown.

The fix: the signal handler marks "shutdown requested" on the controller's ScanManager, and the health check treats deaths seen after that as an expected stop (INFO, no raise). A one-cycle re-check for SIGTERM deaths covers the few-millisecond gap before the handler runs.

D-02 split:
- Unit-proven (this plan): the handler-to-ScanManager wiring, the INFO/no-raise path, the SIGTERM re-check, and the unchanged ERROR path for real deaths.
- Live-proven only (plans 06/07): that tini's group SIGTERM actually kills the scanners with exitcode -15, and that a real restart logs neither error. The lftp `Could not terminate the child` half is a separate mechanism (lftp sits in its own session after setsid) and cannot be reproduced in unit tests, so plan 06's restart cycles are its only proof (RESEARCH Pitfall 2; no lftp code change here).

D-03 verdict (recorded, no code change): the DEFER-SHUTDOWN sleep is not linked. The kernel kills the forked scanners independently of anything the main thread does, and in the failing restart the ControllerJob ran `Controller.exit()` before the 0.5 s sleep had elapsed. The sleep stays and its backlog note stays.
