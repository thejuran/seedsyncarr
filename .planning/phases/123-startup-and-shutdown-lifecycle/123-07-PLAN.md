  <what-built>
    On the Phase 123 PR (draft, not merged):
    - If a part of the app fails while starting up, everything that already started is now shut down, and the failure goes into the existing auto-restart (then the "server down" message if restarts run out). Before, the controller could die silently with leftover processes.
    - If one part fails while shutting down, the other parts are still shut down. The first error is logged.
    - A normal container restart no longer logs the false "Scanner process(es) died unexpectedly" error. The first fix lost a timing race live (123-06). The gap fix waits up to 10 seconds for the app's own shutdown signal before calling a scanner stop a crash; real crashes are still reported.
    - A restart during an active download no longer logs the lftp "Could not terminate the child" error. lftp sometimes took longer than the library's 0.1 s check to die, and was then left behind as a dead, uncollected process. The app now hard-kills and collects it within at most 2 seconds and logs a warning; if it truly will not die, the error still shows.
