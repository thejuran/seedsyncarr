### Phase 124: Model-Stream Overflow Recovery

**Goal**: A slow SSE client that loses incremental model events converges back to the server's current state without unbounded buffering
**Depends on**: Phase 123 (sequencing only; disjoint code paths)
**Requirements**: STRM-01, STRM-02
**Success Criteria** (what must be TRUE):

  1. Overflow is reproduced at the model-stream boundary (bounded `StreamQueue` dropping events for a stalled consumer) with a recorded, repeatable test or script, before any fix is proposed
  2. If reproduction shows an existing recovery guarantee (for example a fresh snapshot already follows a drop), that guarantee is recorded with evidence and STRM-02 closes with no code change
  3. Otherwise, after overflow the slow client's model matches the server's current state (fresh snapshot or reconnect — the smallest mechanism), demonstrated by a test that fails before and passes after
  4. Buffering stays bounded under a stalled consumer; producer atomicity alone is not accepted as the recovery mechanism, and there is no event-bus redesign

## Milestone Summary

**Key Decisions:**

- Owner-approved priority order: credential forwarding, then safety acceptance, startup/shutdown, model-stream overflow, LAN connection tests, release.
- One bounded new wait (lftp reap fallback, at most 2.0 s, only after pexpect's forced close fails) was accepted as an exception to "no new sleeps" (Phase 123 GAP-2, owner 2026-10-26).
- Model-stream overflow recovery reuses the existing SSE connection with one fresh `model-init` snapshot instead of an event-bus redesign (Phase 124).
- The LAN Test Connection guard checks the exact URL the HTTP stack connects to and refuses ambiguous URLs. This is a minor-version behavior change, documented in the 1.8.0 CHANGELOG (Phase 125).
- All open Dependabot PRs were rolled into 1.8.0 by regenerating lockfiles, plus a follow-up PR (#143) for two alerts that appeared after merge (Phase 126).

**Issues Resolved:**

- Late per-episode webhook notice dropped instead of credited, found live in 122-05 and fixed in 122-10/122-13.
- False "Scanner process(es) died unexpectedly" ERROR on `docker restart` (3 of 5 live cycles before the fix, 0 after).
- lftp "Could not terminate the child" on mid-transfer restart (fixed with a bounded process-group reap).
- Pre-existing backslash-URL parser-differential bypass in Test Connection (125 review CR-01).
- Done-group and extract-staging incident records closed with owner-confirmed production cleanup.

**Issues Deferred (ROADMAP Backlog):**

- SIGINT-killed scanners outside the shutdown grace (123 review WR-01).
- Model-stream resync comment accuracy and test tightening (124 review WR-01/WR-02).
- WebAppJob cleanup per-step isolation; controller runtime failures and RECOV-01 auto-restart (123 PR #137 review).
- Arr API key normalization on save (122 review WR-04); post-transfer notice window edge cases; modern RAR volume coalescing.

**Technical Debt Incurred:**

- 119/123/124 VERIFICATION.md frontmatter still shows non-passed statuses (stale or parked minor gaps; see STATE.md Deferred Items).
